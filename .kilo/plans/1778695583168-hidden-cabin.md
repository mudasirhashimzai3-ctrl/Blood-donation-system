# Plan to Fix Mobile App API Access Error on Physical Android Device

## Problem Analysis
The mobile app shows "check your api or network" error when trying to access donor/recipient data on a physical Android device. The issue stems from incorrect API base URL configuration for physical device usage.

## Root Cause
1. The app uses `http://10.0.2.2:8000/api` for Android (emulator-specific alias)
2. Physical devices cannot access `10.0.2.2` as it's an emulator loopback address
3. Backend is likely running on `127.0.0.1:8000` (localhost) which is inaccessible from physical device
4. Missing network configuration to make backend accessible on LAN

## Solution Options

### Option 1: Use adb reverse (Recommended for Development)
1. Connect Android device via USB with USB debugging enabled
2. Run: `adb reverse tcp:8000 tcp:8000`
3. Ensure backend runs on `127.0.0.1:8000` (localhost)
4. App will use `http://10.0.2.2:8000/api` which forwards to device's localhost:8000
5. No code changes required

### Option 2: Use LAN IP Address
1. Find development machine's local IP (e.g., `ipconfig` on Windows)
2. Run backend on `0.0.0.0:8000` (bind to all interfaces)
3. Launch app with: `flutter run --dart-define=API_BASE_URL=http://<LAN-IP>:8000/api`
4. Ensure device and machine are on same Wi-Fi network

### Option 3: Modify AppConfig (Less Flexible)
1. Change `_localDevelopmentApiBaseUrl()` to return LAN IP or use environment variable
2. Requires rebuild when IP changes
3. Not recommended for frequent IP changes

## Implementation Steps

### Backend Preparation
1. Verify Django backend allows connections from device IP:
   - Check `ALLOWED_HOSTS` in settings includes device IP or `*`
   - Ensure CORS settings allow requests from device origin
2. Run backend on appropriate interface:
   - For adb reverse: `python manage.py runserver 127.0.0.1:8000`
   - For LAN IP: `python manage.py runserver 0.0.0.0:8000`

### Device Connection
1. Enable Developer Options and USB debugging on Android device
2. Trust the computer when prompted on device
3. Verify connection: `adb devices` shows device

### Launch Configuration
**For adb reverse method:**
```bash
adb reverse tcp:8000 tcp:8000
flutter run
```

**For LAN IP method:**
```bash
# Get LAN IP (Windows example)
ipconfig
# Note IPv4 Address (e.g., 192.168.1.100)

# Run backend on all interfaces
python manage.py runserver 0.0.0.0:8000

# Launch app with API base URL
flutter run --dart-define=API_BASE_URL=http://192.168.1.100:8000/api
```

### Verification
1. Check debug console for API preflight success message
2. Test donor/recipient data loading
3. Verify no "check your api or network" errors

## Additional Considerations
- Firewall: Ensure port 8000 is allowed on development machine's firewall
- Network: Device and machine must be on same subnet
- HTTPS: If using HTTPS in production, adjust URL scheme accordingly
- Performance: LAN IP method may be faster than adb reverse for data transfer

## Troubleshooting
1. If preflight fails:
   - Verify `adb reverse` is active: `adb reverse --list`
   - Check backend is running and accessible: `curl http://127.0.0.1:8000/core/health/`
   - Ping device IP from machine and vice versa
2. If data loads slowly:
   - Check Wi-Fi network congestion
   - Consider using 5GHz band if available
3. If CORS errors appear:
   - Update Django CORS settings to allow device origin

## Conclusion
The adb reverse method is recommended for development as it requires no IP tracking and works consistently when device is connected via USB. For wireless debugging or when USB isn't available, use the LAN IP method with proper backend binding.
